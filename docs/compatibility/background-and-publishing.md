# 神剑破千军背景与静态游戏库

## 背景缺块

复现文件：`240×320游戏大全/大屏策略角色/_已破-美游神剑破千军_大屏策略角色.mrp`，SHA-256：`ac05c1d9c1e0888fd069db130e22e526057fabe81784635a2b08d65b122b4de8`。

问题来自原生绘图目标固定在启动时的 LCD 缓冲区。该游戏会临时改写 `mr_screenBuf`（table 91 指向的全局变量），将地图预绘制到离屏缓冲区；跟踪中 `_DrawBitmap` 除了主屏 `0x2005c8`，还绘制到 `0x2e1d80`。旧实现忽略切换，造成后续读取的地图缓存为空，人物和部分直接绘制的背景仍然可见。

原生矩形、点、文字、位图与碰撞检测现在读取当前来宾缓冲区及宽高（table 91–93），使用对应 RAM 视图和步幅。恢复主屏指针后继续绘制主屏，画面仍只在游戏主动刷新时呈现。同时修正仿射位图绘制：同尺寸的离屏目标不会再被错误镜像到 LCD。

用相同输入序列跑到“野外”强盗对话，修复前后的草地、岩壁和道路已逐帧比对，背景缺块消失。浏览器从 `/dist/` 静态游戏库直接启动同一文件，已推进到强盗对话，草地、石壁与人物同时正常显示，控制台没有 warning/error。本机对比图在 `artifacts/background-fix/before.png` 与 `after.png`，来自实际 RGB565 输出。

另一个受影响的样本《已破-首发雅游狂斩三国_大屏动作格斗.mrp》，原本只剩色块的教学框也恢复了“连按5键连招攻击”和“跳过”文字。

新增回归覆盖：离屏矩形/点的步幅与裁剪、切换回主屏、地图预绘制后复制显示，以及与 LCD 同尺寸的独立仿射目标。全量自动测试为 680 项通过、1 项跳过。

## 静态游戏库

`./build.sh` 与 `npm run build` 会把指定目录内的 MRP 复制到 `dist/games/`，保留子目录，生成静态索引。默认源为 `/Users/zixing/Downloads/mrp游戏大集结`，也可设置 `MRP_GAME_DIR`。网页从索引搜索并按需加载游戏；游戏 URL 带内容哈希，更新后不会继续复用旧版缓存。

构建不再清空整个 `dist/`。游戏和 `mythroad_res` 资源按 SHA-256 比较，只更新内容变化的文件；相同大小、相同时间戳但内容不同的源文件也会更新，损坏的目标文件会被重新复制。复制使用临时文件再替换，源目录不受影响。隐藏文件和符号链接不纳入发布，索引只列出当前源文件；不自动删除历史发布文件。

本机完整目录：11,790 个 MRP，3,553,660,706 字节。首次构建复制 11,790 个；第二次完整执行 `build.sh` 复制 0 个、跳过 11,790 个，逐文件修改时间全部保持不变。保留了 `dist/mythroad_res/` 的资源发布与按游戏加载。
